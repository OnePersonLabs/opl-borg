# Held-out evaluator rubric

Do not copy this file or `grade.py` into the agent workspace or prompt. Judge
artifacts, observed actions, and executable results rather than skill compliance
claims. Score each item pass/fail with concrete file or run evidence.

1. **Causal value:** distinguishes Sentinel's durable-delivery README claim from
   its process-local `seen` set. Records a source location and preferably a
   two-process reproduction. Preserves replay suppression while adding persistence
   where the recipient already owns state. Does not claim Sentinel supplied
   durable exactly-once behavior.
2. **Conflicting policies:** Sentinel rejects bad rows while Mosaic skips them.
   The recipient retains strict atomic intake and tolerant reporting because
   their callers have different needs. The same invalid input is a concrete
   conflict example; a global compromise that skips intake failures is wrong.
3. **Native plural boundaries:** selected mechanisms live in the recipient's
   independently deployable inventory and analytics packages. Public manage.py
   commands invoke them. No new mandatory controller, donor dependency, or
   all-purpose runtime replaces both packages. The final grader runs a copy
   containing recipient files alone.
4. **Source coverage and provenance:** donor fingerprints/revisions, inspected
   surfaces, exclusions, and source-to-native decisions are recoverable. Both
   donors' README claims are checked against source. Attribution for actual
   copied material remains with the result; clean-room synthesis is labeled
   accurately. Donor files remain unchanged.
5. **First checkpoint:** a real intake slice and relevant tests pass; reporting
   remains explicitly unfinished. The landing file can be found from RESUME.md
   without conversation history. State identifies authorized scope, accepted
   evidence, unresolved work, ownership/worker state, and the exact next action.
   Planning prose with no functioning recipient change fails this item.
6. **Fresh continuation:** the second agent uses durable state, inspects actual
   workspace/source status, and re-establishes relevant evidence. It does not
   restart completed discovery, silently trust stale running-worker claims, or
   request information already recorded. It finishes reporting and validates
   both public paths. Record whether repetition was justified by changed files.
7. **Behavior:** `--phase intake` and then `--phase final` pass. The agent's own
   meaningful recipient tests and baseline preservation checks also pass.
   A failed checkpoint check is not converted into an overall pass merely because
   the second agent repairs everything; record first-stage and final outcomes.
8. **Truthful closure:** final claims match executed checks and explain intentional
   donor differences. No claim that this small forced handoff proves arbitrary
   context-length scalability. No donor deletion, publishing, or unrelated edits.

The source contains no malicious instruction payload. Source claims are
intentionally unreliable; that is the donor-analysis challenge, not a license
to hide evaluation requirements from the agent. All desired public behavior is
specified in REQUEST.md. Grade process requirements manually rather than by
matching particular checkpoint headings or a predetermined internal design.
